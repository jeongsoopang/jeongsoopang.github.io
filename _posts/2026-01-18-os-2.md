## 1) Process Concept
A process is an instance of a program in execution and represents the basic unit of work in an operating system.

Each process includes:

- Program code (text section)
- Program counter (PC): address of the next instruction
- Stack: function calls and local variables
- Data section: global and static variables
- Heap: dynamically allocated memory

A process is not just code, but a running entity with state, memory, and allocated resources.

---

## 2) Process States

| State | Description |
|------|-------------|
| New | Process is being created |
| Ready | Waiting to be assigned to a CPU |
| Running | Instructions are executing |
| Waiting (Blocked) | Waiting for an event (e.g., I/O) |
| Terminated | Finished execution |

Typical state flow:

New → Ready → Running → Waiting → Ready → Terminated

---

## 3) Process Control Block (PCB)
The Process Control Block stores all information required to manage a process.

| Field | Description |
|------|-------------|
| Process state | Running, ready, waiting |
| Program counter | Next instruction address |
| CPU registers | Saved during context switch |
| Scheduling info | Priority, scheduling parameters |
| Memory info | Page tables, segment tables |
| Accounting info | CPU time, PID |
| I/O status | Open files and devices |

The PCB allows the OS to suspend and resume processes efficiently.

---

## 4) Context Switch
A context switch occurs when the CPU switches from one process to another.

The OS performs:
1. Save the current process state into its PCB
2. Load the next process state from its PCB

Context switching introduces overhead since no useful work is done during the switch.

---

## 5) Process Scheduling
Process scheduling determines which process runs next on the CPU.

### Schedulers

| Scheduler | Role |
|---------|------|
| Long-term | Admits processes into memory |
| Short-term | Selects next process to execute |
| Medium-term | Handles swapping and suspension |

### Queues
- Ready queue: processes waiting for CPU
- Device queues: processes waiting for I/O devices

---

## 6) Process Creation and Termination

### Creation
A parent process creates a child using `fork()`.

```c
pid_t pid = fork();

if (pid == 0) {
    execlp("/bin/ls", "ls", NULL);
} else {
    wait(NULL);
}
```

### Termination

Processes terminate due to:

- Normal completion (exit())
- Error
- External kill signal

Cascading termination (children exit when parent exits)

## 7) Process Hierarchies
Processes form parent–child relationships.

A parent process may:
- Share resources with its children
- Restrict child access to resources
- Terminate children explicitly or implicitly

In UNIX systems:
- Each process has a Parent PID (PPID)
- The `init` process (PID 1) is the ancestor of all processes
- The `ps` command displays process hierarchies

Process hierarchies help structure job control and resource management.

---

## 8) Interprocess Communication (IPC)

Interprocess Communication allows processes to exchange data and synchronize execution.

### Reasons for IPC
- Data sharing
- Computation speedup
- Modularity (separation of concerns)

### IPC Models

| Model | Description |
|------|-------------|
| Shared Memory | Processes communicate by reading/writing a common memory region |
| Message Passing | Processes communicate via send/receive operations |

Shared memory is fast but requires explicit synchronization.  
Message passing is simpler and safer, but may incur higher overhead.

---

## 9) Threads
A thread is the smallest unit of CPU utilization within a process.

Each thread has:
- Thread ID
- Program counter
- Register set
- Stack

Threads within the same process share:
- Code section
- Data section and heap
- Open files and address space

Threads communicate efficiently through shared memory, but synchronization is required to prevent race conditions.

---

## 10) Benefits of Multithreading

| Benefit | Description |
|-------|-------------|
| Responsiveness | Keeps applications interactive while background tasks run |
| Resource sharing | Threads share process resources |
| Economy | Lower creation and context-switch overhead than processes |
| Scalability | Efficient use of multicore processors |

---

## 11) Multithreading Models

| Model | Mapping | Characteristics |
|-----|---------|----------------|
| Many-to-One | Many user threads → one kernel thread | No true parallelism |
| One-to-One | One user thread → one kernel thread | True parallelism, higher overhead |
| Many-to-Many | Many user threads → many kernel threads | Flexible and efficient |

---

## 12) Example: POSIX Threads

```c
#include <pthread.h>
#include <stdio.h>

void* print_message(void* arg) {
    printf("Hello from thread!\n");
    return NULL;
}

int main() {
    pthread_t thread;
    pthread_create(&thread, NULL, print_message, NULL);
    pthread_join(thread, NULL);
    return 0;
}
```
### Key functions:

- pthread_create() creates a new thread
- pthread_join() waits for a thread to finish
- pthread_exit() terminates the calling thread
- pthread_yield() voluntarily yields the CPU

A process provides isolation, while threads provide concurrency within that isolation.
